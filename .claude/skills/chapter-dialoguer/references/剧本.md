# 05 剧本

> galgame 剧本格式——把「逐句对话 + 立绘 + 场景 + 分支」固化成结构化数据。**创作区（`25_剧本/`）用 台词.jsonl（JSONL 逐句一行，单句可独立修改），运行时（`99_game/`）用 JSON（Godot 直接消费，由 `chapter-publisher` 投影合并）**。
> **纯 skill 生成**；本文件只定义格式，不涉及生成流程。

---

## 定位

- **剧本独立**：剧本是逐句对话的第一公民，自包含分支；与 [Schema总览.md](../../../../00_init/Schema总览.md) 的图数据（Character/Event/Choice/立绘）**不双向导航**。图退为设计/分析用途（规划分支结构、给生成 skill 参考），运行时不消费图。
- **创作区 JSONL / 运行时 JSON**：创作区 `台词.jsonl` **逐句一行**（每行自包含：改一句只碰一行，git diff 行级清晰）；`chapter-publisher` 发布时投影合并成 `.json`，Godot 原生 `JSON.parse` 直接读，零运行时构建步骤。
- **台词与演出分离**：台词文件只含「谁说了什么 / 旁白说了什么 + 分支控制」；感官演出（BGM/背景/立绘出场）**不入台词文件**——BGM 走图 `Scene -[:has_bgm]-> BgmTrack`（发布注入 scene-block）、背景 = scene 行的 scene 名、立绘出场 = say 自带槽位（随说话人出现）。
- **唯一衔接**：剧本只写**逻辑名**（角色/立绘/场景/曲目），经一张 **manifest** 映射到实际资源路径；manifest 可由现有美术生产链产物自动生成。剧本与资源解耦。

---

## 数据模型

层级：**章节文件 → 场景段 → 指令序列**。指令序列扁平，分支靠 `label` + 跳转。

```mermaid
flowchart LR
    File["台词.jsonl（节级，逐句一行）"] --> Meta["meta 行（首行）"]
    File --> Scene["scene 行（分隔）"]
    Scene --> Lines["say / narrate / choice / ... 行"]
    Lines -.->|"jump / choice"| Scene2["另一 scene 行"]
    Scene2 -.->|"file"| File2["另一章节（章 JSON）"]
```

---

## 文件组织

- **一个章节 = 创作区每节一个 `台词.jsonl` 文件 + 运行时一个合并后的 `.json` 文件**。创作按节进行：`chapter-dialoguer` 为每节产出 `chapter<NN>_<章概述>/sec<MM>_<节概述>/台词.jsonl`（节级定稿，挂 `SecScript.script_path`）；`chapter-publisher` 在全章各节定稿就绪后，把它们**投影合并**成单一 `99_game/data/chapters/chapter<NN>_<章概述>.json`（章级运行时文件，同名主体即章节标识）。章节划分建议对齐 [大纲.md](../../../../00_init/大纲.md) 的叙事段落。
- 章节内含该章**完整对话**。
- 跨章节跳转用 `file`（不带扩展名）指向目标章节文件名。
- **章节与图的关系**：每个运行时章节 JSON 对应图中的 `Chapter` 节点；章下挂若干 `Section` 节点（`has_section` 边，纯编排容器），每节经产物链挂 `SecOutline.outline_path`（创作区节级 `outline.md` 提纲）与 `SecScript.script_path`（`台词.jsonl` 定稿）。编排信息（标题/序号/分节/场景顺序/分支骨架）入图作设计层，逐句对话不入图——运行时只读本 JSON，图仅供生成与分析（见 [Schema/剧情.md](../../../../00_init/Schema/剧情.md)）。
- **创作区与运行时区分离**：剧情侧 skill（`chapter-structurer` 章级 → `chapter-outliner` → `chapter-dialoguer` → `section-voice-publisher` 节级 → `chapter-publisher` 章级发布）产出的提纲与台词先落 **`25_剧本/`**（创作/审阅区，`SecOutline.outline_path` / `SecScript.script_path` 指向节级文件，dashboard 在此逐节预览/审批/逐句音频审）；各节定稿+逐句音频审通过（`SecScript.status=11` ∧ `LineAudio.status=11`）且所需立绘就绪后，由 `chapter-publisher` 把全章各节台词**投影合并** + 涉及的立绘/背景/BGM 资源打包发布到 **`99_game/data/chapters/`** + `99_game/assets/`（Godot 运行时消费区）。两区解耦：改 `25_剧本/` 不影响已发布版本。

## 创作区 台词.jsonl 与运行时章 JSON 的边界

| 区域 | 路径 | 格式 | 谁产出 | 进 schema 校验？ |
|------|------|------|--------|------------------|
| 创作区提纲（节级） | `25_剧本/chapter<NN>_<章概述>/sec<MM>_<节概述>/outline.md` | Markdown | `chapter-outliner` | 否（含 `authoring` 人读字段） |
| 创作区台词（节级） | `25_剧本/chapter<NN>_<章概述>/sec<MM>_<节概述>/台词.jsonl` | JSONL 逐句一行 | `chapter-dialoguer` | 是（行级校验 + 投影后章 JSON schema） |
| 运行时定稿（章级合并） | `99_game/data/chapters/chapter<NN>_<章概述>.json` | JSON | `chapter-publisher`（投影合并） | 是（合并后复校） |

- **创作区 台词.jsonl**：UTF-8、每行一个紧凑 JSON 对象（中文直出 `ensure_ascii=False`）。**单句修改契约**：改一行只碰一行——所有程序化写回（`voice_bundler bind-audio`、dashboard 审批动作）一律经 [jsonl_script.py](../../../../.claude/scripts/jsonl_script.py) 的 `save`（逐行序列化、未改行字节不变），禁止裸写。
- **创作区提纲 Markdown**（`outline.md`）：纯人读人改——拓扑骨架用 `key: value` 行 + 反引号标契约值，`authoring` 散文为 md 正文自由换行。不进 schema（详见「提纲格式」节）。
- **运行时 JSON**：Godot `JSON.parse` 直接消费；由 `chapter-publisher` 用 [merge_sections_to_chapter.py](../../../../99_game/tools/merge_sections_to_chapter.py) 把全章各节台词按节序投影合并（`scenes[]` 纯拼接，`meta.requires` 取并集，portrait 整键改写 + BGM 注入），再用 [validate_chapter.py](../../../../99_game/tools/validate_chapter.py) 复校。
- **投影规则**（`jsonl_script.project`）：台词行的 `id` 与 `audio` 字段被丢弃；say 行的 `audio.key` 投影为 `voice`；**emotion 不投影**（运行时不消费）。章 JSON 的 `meta` 取章节点值 + 各节 `requires` 并集。跨章节 `file` 引用用章 stem（不带后缀）。

### JSONL 写作安全规则（仅约束 `台词.jsonl`）

> `outline.md` 是纯 Markdown，**不适用**以下规则。以下规则约束会被投影进运行时 JSON 的台词行。

1. **每行一个紧凑 JSON 对象**，中文直出（`ensure_ascii=False`）；行内字符串含双引号/反斜杠按 JSON 转义。
2. **台词行 `id` 字段在最前、`op` 其次**（稳定 diff 与人扫读）。
3. **行 id `L<NNNN>` 节内递增永不复用**；水位在 meta 行 `line_seq`（= 下一个可分配号）。手改/插入行 = 取当前水位作 id 且 `line_seq+=1`；删行不动水位。validate 强校验「id 唯一 ∧ 数值 < line_seq」。
4. **say 四字段**（who/portrait/pos/text），**禁写 `emotion`/`voice` 顶层字段**（emotion 由配音期判别入 `audio.emotion`；voice 由 `audio.key` 投影）；`audio` 对象只由配音工具（bind-audio）与 dashboard 审批动作写入。
5. **不加任何额外字段**（authoring 散文绝不搬进台词；投影 schema `additionalProperties:false`）。
6. **scene 行 `id` 沿用 structurer 预分配的章内唯一 id**，不自创（保证合并时跨节 jump 不冲突）。

## 提纲格式（outline.md）

`chapter-outliner` 产出**节级**提纲，落盘 `25_剧本/chapter<NN>_<章概述>/sec<MM>_<节概述>/outline.md`（**纯 Markdown，人读人改**）。提纲 = **拓扑骨架（`key: value` 行 + 反引号标契约值）+ `authoring` 人读散文**，同处一个 md 文件。

> **为什么是 md 而非结构化格式**：提纲是纯人读 + LLM 读的中间产物——不被任何 Python 解析、不进 schema 校验、唯一消费者是 `chapter-dialoguer`（LLM）。结构化语法的引号/缩进约束，对人改作者意图（direction / beats 等长散文）是纯负担。Markdown 让拓扑骨架保持可机读契约的同时，authoring 散文自由换行、零语法约束。

### 拓扑骨架（chapter-dialoguer 必须原样搬进台词）

用 md 的 `- key: value` 行表达；**反引号标注的值是契约值，搬进 台词.jsonl 时必须原样、不得改写**：

- **资源清单**：`- 出场角色：`角色名``、`- 场景：`场景名``（提纲段**不列立绘变体**，细节对话段才补）。
- **每个场景段**：二级标题 `## 场景段：`id`` 下挂 `- 场景：`场景名`` / `- 时段：清晨` / `- BGM 倾向：`（散文写音乐情绪定位，**不是 track 名**——BGM 走图关联，供 `bgm-designer` 与 dialoguer 兜底建 BgmTrack 参考）。
- **分支拓扑**（对应台词分支行占位）：仅在存在 `choice` / `jump` / `ending` 时用 md 列表写出，如 `- choice：选项「label」→ scene `id`（leads_to_ending）`、`- jump → file `chapter01_新皮肤``。无分支的段此节留空（dialoguer 填逐句对话）。

### authoring 人读散文（不进台词，仅供 dialoguer 参考；不进 schema）

| md 章节 | 旧字段名 | 位置 | 含义 |
|------|------|------|------|
| `## 方向` | `direction` | 节级 | 一段话讲清**本节**剧情发展方向（核心字段） |
| `## 情感弧` | `emotion_arc` | 节级 | 情感弧线起点 → 终点 + 中途转折 |
| `## 约束` | `constraints` | 节级 | 给 dialoguer 的硬约束清单 |
| `### 职责` | `purpose` | 每场景段 | 这场戏的戏剧职责 |
| `### 节拍` | `beats` | 每场景段 | 节拍走向（自然语言列表，**禁写台词**）—— 解决事件粒度粗，给 dialoguer 节拍依据 |
| `### 母题锚点` | `motif_anchors` | 每场景段 | 母题 / 象征物锚点 |
| `### 衔接` | `transition` | 每场景段 | 场景衔接方式说明 |

提纲确定「本节分几段、每段场景/时间、choice 分叉与汇合、ending 位置」的骨架；`chapter-dialoguer` 读提纲文件，以「节拍（beats）」章节为节拍依据，在**保持拓扑契约值不变**的前提下填充逐句 `say` / `narrate` / 分支行，产出 `台词.jsonl`。**authoring 散文不搬进台词**。

> 提纲本身**不是** `剧本.schema.json` 的校验对象（它是台词的中间产物，含 authoring 人读字段）；只有 `chapter-dialoguer` 产出的 台词.jsonl 必须通过校验（行级 + 投影 schema）。

## 台词.jsonl 行类型（8 种）

每行一个 JSON 对象，用 `op` 区分。台词行（非 meta/scene）另带稳定 `id`。

| op | 行类型 | 说明 |
|----|--------|------|
| `meta` | 首行保留行 | `{op, chapter, title, requires, line_seq}`；节内唯一 |
| `scene` | 场景分隔行 | `{op, id, scene, time?}`；开一个 scene-block（到下一 scene 行或 EOF） |
| `say` | 台词行 | `{id, op, who, portrait, pos, text, audio?}` |
| `narrate` | 旁白行 | `{id, op, text}` |
| `choice` | 选择点行 | `{id, op, options[]}`（结构同运行时） |
| `label` | 锚点行 | `{id, op, name}` |
| `jump` | 跳转行 | `{id, op, to?/scene?/file?}` |
| `ending` | 结局行 | `{id, op, kind, title?, cg?}` |

> **移出台词文件的 5 种演出 op**（原 `show`/`hide`/`bg`/`bgm`/`sfx`）：立绘出场 = say 自带槽位（随说话人出现，无需 show）；背景 = scene 行的 scene 名（进入 scene-block 自动切）；BGM = 图 `Scene-has_bgm->BgmTrack`（发布注入 scene-block.bgm）；sfx = V1 无需求（未来需要时作为新行类型扩展，JSONL 可扩展不破坏）。

### meta 行

| 字段 | 中文 | 类型 | 必填 | 说明 |
|------|------|------|------|------|
| chapter | 章节 | int / string | 是 | 章节编号（`0` 是合法值——序章） |
| title | 标题 | string | 是 | 节标题 |
| requires | 资源清单 | object | 否 | 本节用到的逻辑名（characters/scenes/portraits 子字段同运行时 meta.requires） |
| line_seq | 行 id 水位 | int | 是 | 下一个可分配行号（已分配最大号 + 1）；插入行取 `L<line_seq>` 作 id 后自增 |

### scene 行

| 字段 | 中文 | 类型 | 必填 | 说明 |
|------|------|------|------|------|
| id | 段标识 | string | 是 | **全章节内唯一**（跨节不重复），供跳转定位；由 `chapter-structurer` 在分节规划时预分配 |
| scene | 场景 | string | 是 | 背景场景逻辑名（→ manifest → 场景图） |
| time | 时段 | string | 否 | 氛围标注：清晨 / 白天 / 黄昏 / 夜晚 |

> 进入场景段（投影后 scene-block）：自动套用其 `scene` 背景 + 图注入的 `bgm`。

### say 行

| 字段 | 中文 | 类型 | 必填 | 说明 |
|------|------|------|------|------|
| id | 行 id | string | 是 | `L<NNNN>` 节内唯一、永不复用（voice key 末段） |
| who | 角色 | string | 是 | 角色逻辑名 |
| portrait | 立绘 | string | 是 | 立绘变体键（纯变体如 `慵懒`）；与 who 组合为 `<who>.<portrait>` |
| pos | 站位 | enum | 是 | `left` / `center` / `right` |
| text | 台词 | string | 是 | 对话文本 |
| audio | 音频 | object | 否 | 配音后处理注入（**dialoguer 不写**），见下 |

`audio` 对象（`section-voice-publisher` 的 `bind-audio` 写入；dashboard 逐句审批动作改其 `status`）：

| 字段 | 说明 |
|------|------|
| key | voice 资源键 `<char>-<chapter_stem>-<scene_id>-<line_id>`（= wav 文件名 = manifest.voices 键 = 投影后 say.voice，单一来源 `voice_bundler.make_voice_key`） |
| emotion | 配音期判别的情绪标签（12 词表，[emotion_instruct.json](../../../../.claude/scripts/voice/emotion_instruct.json)）——**创作期不写**，由 voice-publisher 按台词上下文逐句判别 |
| status | 行级审批三态：`pending` / `approved` / `rejected` |
| attempts | 生成次数（驳回重生成 +1） |
| text_sha1 | 生成时台词的 sha1——判「台词改了没」（stale：不匹配则重配时自动重挑） |

> **每条 `say` 必带立绘**：渲染该条时，将该角色立绘按 `pos` 放置。运行时按 `pos` **累积维持**各位置立绘——A 放 `left` 后，B 的 `say` 放 `right`，A 仍在 `left`，直到被同位置新 `say` 覆盖。独白布局用 `center`。
>
> **`voice` 语音字段（运行时）**：投影时由 `audio.key` 生成，运行时 `Game._on_line_ready` 拿 voice 键 → `manifest.voices` → `AudioManager.play_voice` 同步播音；`narrate` 触发 `play_voice("")` 仅停不播。**行 id 稳定寻址**——插入/删除/移动行不改变其他行的 key，台词被改的句由 stale 机制自动重配。

### narrate 行

| 字段 | 中文 | 类型 | 必填 | 说明 |
|------|------|------|------|------|
| id | 行 id | string | 是 | `L<NNNN>` |
| text | 文本 | string | 是 | 旁白 / 环境叙述 |

> `narrate` 不携带立绘，**维持当前画面**。

### choice / label / jump / ending 行

结构与运行时章 JSON 的同名指令一致（额外带 `id`）：

- `choice`：`options[]` 每项含 `label`(是) + `to`/`scene`/`file` 至少其一 + `leads_to_ending`(否)。
- `label`：`name`(是，所在场景段内唯一)。
- `jump`：`to`(否) · `scene`(否) · `file`(否)；至少含其一。
- `ending`：`kind`(是，`BE`/`TE`/`HE`/`NE`) · `title`(否) · `cg`(否)。

## 运行时章 JSON 结构（投影产物，格式不变）

```json
{
  "meta": { ... },
  "scenes": [ {场景段}, {场景段}, ... ]
}
```

### meta

| 字段 | 中文 | 类型 | 必填 | 说明 |
|------|------|------|------|------|
| chapter | 章节 | int / string | 是 | 章节编号或标识 |
| title | 标题 | string | 是 | 章节标题 |
| requires | 资源清单 | object | 否 | 本章节用到的逻辑名（各节并集），供运行时预加载 + manifest 校验 |

`requires` 子字段：`characters`（角色名数组）/ `scenes`（场景名数组）/ `portraits`（发布时已改写为 guid 整键）。

### 场景段（scene block）

| 字段 | 中文 | 类型 | 必填 | 说明 |
|------|------|------|------|------|
| id | 段标识 | string | 是 | 来自 scene 分隔行；章内唯一 |
| scene | 场景 | string | 是 | 背景场景逻辑名 |
| time | 时段 | string | 否 | 氛围标注 |
| bgm | 音乐 | object | 否 | **发布注入**（图 `Scene-has_bgm->BgmTrack`，status=2）：`{track, mode, loop}` |
| lines | 指令序列 | array | 是 | 投影后的指令（丢 id/audio；say.voice = audio.key） |

## 跳转寻址

`to` / `scene` / `file` 三者组合，层层可选：

| 组合 | 含义 |
|------|------|
| `to` | 当前场景段内 label |
| `scene` | 本章节内该 id 的场景段（从头） |
| `scene` + `to` | 本章节该段的 label |
| `file` | 跨章节文件（从头） |
| `file` + `scene`(+`to`) | 跨章节到指定段（的 label） |

> `choice` 选项与 `jump` 共用此寻址。

## 资源引用与 manifest

剧本只写逻辑名，不经 manifest 不知资源路径。manifest 把逻辑名映射到实际文件：

```json
{
  "portraits": {
    "陈默.沉重": "07_角色美术/陈默/沉重.png"
  },
  "scenes": {
    "长江大桥-栏杆": "07_场景美术/长江大桥/栏杆/background.png"
  },
  "bgm": { "夜风": "assets/bgm/夜风.ogg" },
  "sfx": {},
  "voices": { "陈默-chapter01_新皮肤-s01_桥上-L0002": "assets/voices/陈默-chapter01_新皮肤-s01_桥上-L0002.wav" },
  "cg":  {}
}
```

- **立绘逻辑名** `<角色>.<变体>` ↔ [StandingIllustration](../../../../00_init/Schema/角色美术.md) 的表情 / 动作变体；资源路径取其 `image_path`。
- **场景逻辑名** ↔ [Scene](../../../../00_init/Schema/场景美术.md) 的 `name`；V1 对话场景仅用 background 层。
- **BGM track 名** ↔ [BgmTrack](../../../../00_init/Schema/声音.md) 的 `name`（`Scene-has_bgm->BgmTrack` 关联；发布时 status=2 的拷 `assets/bgm/<name>.wav` + manifest.bgm 图驱动更新）。
- manifest 可由美术生产链产物自动生成；换图 / 改路径不动剧本。

> **立绘 guid 整键（搬运层去冲突）**：创作区台词的 `portrait` 永远写纯变体（`慵懒`）。当同角色换装导致两套立绘同名时，`chapter-publisher` 搬运时用 [generate_portrait_map.py](../../../../99_game/tools/generate_portrait_map.py)（产出 chapter-map：portraits + bgm 两段）把 `say.portrait` 改写为 guid 整键 `<char>-<costume>-<variant>-<stand_id>`（`stand_id` = 图 `StandingIllustration.id`，全局唯一），manifest 键、PNG 文件名同源对齐（[portrait_key.make_key](../../../../99_game/tools/portrait_key.py)）。运行时 [PortraitLayer](../../../../99_game/scripts/ui/PortraitLayer.gd) 直接用 portrait 字段整键查 manifest。创作区台词与 `variant_label` 不感知此机制。

> **运维约束**：给已有角色新增一套着装会改变 manifest 键（全图重跑 `manifest_builder.py`），但旧章 JSON 仍引用搬运时的键——已发布章不受影响；仅当旧章需要纳入新着装时才重搬该章。

## 运行时消费（简述）

Godot 侧：**只读 `chapter-publisher` 投影合并后的 `.json`**（创作区 `台词.jsonl` 不进 Godot）→ `JSON.parse` → JSON Schema 校验 → 解释器维护指令指针逐条执行——阻塞指令等输入、即时指令即进、`jump` 移指针、`ending` 终止。场景段切换时套用其 `scene` + 注入的 `bgm`；立绘按 `say` 的 `who + portrait + pos` 渲染并累积维持。

> 具体实现不在本格式 spec 范围。

## V1 边界

**含**：章节 → 场景段 → 指令序列结构；台词 8 行类型（+ 运行时保留完整 11 指令定义供历史章 JSON 兼容）；`say` 必带立绘；`meta.requires`；manifest 资源映射；行级校验 + schema 校验；行级音频三态审批。

**不含（YAGNI）**：变量 / flag、条件分支（`if`）；特效（wait / shake / flash）；独立 CG 指令（结局 `cg` 字段除外）；存档指令（运行时在选择点 / 场景段头自动存档）；多图层场景；时段驱动的背景变体；skill 生成流程；台词内 sfx 行（未来扩展）。

> 所有分支由 `choice` 直接跳转表达，运行时无状态。未来若需好感度 / flag 驱动分支，再扩 `set` / `if` 指令。

## 命名规则

- 创作区目录结构（按章/节分层）：

  ```
  25_剧本/chapter00_序章/         # 章 = chapter<NN>_<章概述>
  ├── 设计简报.md                  # 章级（structurer 产，挂 Chapter.brief_path）
  ├── sec00_酒店醒来/              # 节 = sec<MM>_<节概述>
  │   ├── outline.md             # 节级提纲（outliner 产）
  │   └── 台词.jsonl              # 节级台词（dialoguer 产）
  ├── sec01_意外突生/
  │   ├── outline.md
  │   └── 台词.jsonl
  └── sec02_灵魂夹缝/
      ├── outline.md
      └── 台词.jsonl
  ```

  `<NN>`=`chapter_no`、`<MM>`=`section_no` 零填充；<章概述>/<节概述> 取 title 核心主题，清洗 Windows 非法字符。运行时章文件仍为 `99_game/data/chapters/chapter<NN>_<章概述>.json`（章 stem，publisher 投影合并各节，运行时不感知节层）。
- 场景段 `id`：**全章节内唯一**（跨节不重复），由 `chapter-structurer` 预分配（建议 `s<MM>_<short>`，如 `s01_桥上`）。
- 台词行 `id`：`L<NNNN>` 节内唯一、永不复用（水位 `meta.line_seq`）。
- `label.name`：所在场景段内唯一。
- 逻辑名：角色用姓名；立绘 `<角色>.<变体>`；场景对齐 `Scene.name`；BGM track 对齐 `BgmTrack.name`。
