# 01 叙事基础

> 角色、事件、地点、信息、选择分叉——故事世界的 5 种基本实体。

---

## 节点

### 角色（Character）

最小粒度：每个有名字的真实人物。

| 字段 | 中文 | 类型 | 必填 | 示例 |
|------|------|------|------|------|
| id | 编号 | string | 是 | snowflake Base62 |
| name | 姓名 | string | 是 | `陆择` |
| gender | 性别 | enum | 否 | `男` / `女` |
| description | 简介 | string | 否 | `星耀电竞战队队长，沉默寡言的天才选手` |
| birth_year | 出生年份 | int | 否 | `2003` |
| character_tags | 人设标签 | string | 否 | `沉默寡言, 外冷内热, 完美主义` |
| color_direction | 配色逻辑 | string | 否 | 自由文本：主辅点缀色与明暗逻辑（由 char-concept-designer 填充） |
| priority | 优先级 | enum | 否 | `P0` / `P1` / `P2`：制作优先级，P0 最优先（分组见 [00_init/大纲.md](../../00_init/大纲.md)） |

---

### 事件（Event）

最小粒度：某时某刻发生的某件事。一个事件 = 一个有明确时间点的具体动作或状态变化。

| 字段 | 中文 | 类型 | 必填 | 示例 |
|------|------|------|------|------|
| id | 编号 | string | 是 | snowflake Base62 |
| title | 标题 | string | 是 | `陆择加入星耀电竞` |
| time | 时间 | Date | 是 | `2024-04-11` |
| description | 描述 | string | 否 | |
| type | 类型 | enum | 否 | `行动` |
| ending_kind | 结局类型 | enum | 否 | `BE` / `TE` / `HE` / `NE`（非结局留空） |

**type 枚举**：
- `行动`：具体的物理行为，如跳江、转账、报警
- `交流`：对话、发帖、聊天记录等沟通行为
- `转折`：改变事态走向的关键节点
- `状态变化`：人物状态或关系状态的改变，如分手、确诊

**ending_kind 枚举**（结局事件标记，可选）：`BE` Bad Ending / `TE` True Ending / `HE` Happy Ending / `NE` Normal Ending。非结局事件不填。结局事件由 [剧情.md](剧情.md) 的 `Choice -[option {leads_to_ending:true}]-> Event` 指向。

---

### 地点（Location）

最小粒度：具体地点/游戏场景。

| 字段 | 中文 | 类型 | 必填 | 示例 |
|------|------|------|------|------|
| id | 编号 | string | 是 | snowflake Base62 |
| name | 名称 | string | 是 | `重庆长江大桥` |
| description | 描述 | string | 否 | `横跨长江的公路铁路两用桥` |

---

### 信息（Info）

最小粒度：每条对读者有意义的新认知。一条信息 = 一个之前不知道的事实。

| 字段 | 中文 | 类型 | 必填 | 示例 |
|------|------|------|------|------|
| id | 编号 | string | 是 | snowflake Base62 |
| title | 标题 | string | 是 | `陆择是孤儿` |
| content | 内容 | string | 是 | `陆择从小在孤儿院长大，从未见过亲生父母` |
| knowledge_level | 知识层 | enum | 是 | `2` |

**knowledge_level 枚举**：
- `1`：表层——新闻报道、警方通报等公开信息
- `2`：参与层——需要阅读聊天记录、转账记录等细节才能了解的信息
- `3`：深层——需要综合推断或获取非公开信息才能理解的隐性事实

---

### 选择分叉（Choice）

最小粒度：一个玩家选择分叉点。把 galgame「玩家选择」一等公民化——显式建模「在哪选择、不同选项导向不同后续」。

大纲设定：灵魂穿越者只能在关键选择节点干预，而关键选择节点 = 玩家的选择项。

| 字段 | 中文 | 类型 | 必填 | 示例 |
|------|------|------|------|------|
| id | 编号 | string | 是 | snowflake Base62 |
| name | 名称 | string | 是 | `跳江选择` / `三选一` |
| description | 情境 | string | 否 | 选择发生的情境描述 |
| time | 时间 | string | 否 | `Day 0 深夜` / `Day 22` |

> Choice 无 status 字段、不参与生产流水线，与 Character/Event/Location/Info 同属纯数据实体。

**结局**：结局不单独建节点，仍用 `Event` + 可选属性 `ending_kind`（`BE`/`TE`/`HE`/`NE`）表达；`option{leads_to_ending:true}`（见下）指向的 Event 即结局事件。

---

## 边

> 所有边方向：**上游 → 下游**。`sync` 属性控制级联同步。

### relation — 人物关系 `N:N`

- **方向**：`Character → Character`

| 属性 | 中文 | 类型 | 必填 | 说明 |
|------|------|------|------|------|
| type | 关系类型 | string | 是 | 如"恋爱""亲属""同事""仇人" |
| detail | 详情 | string | 否 | 如"恋爱中""已分手""姐弟" |
| start_time | 开始时间 | Date | 否 | 关系建立的时间 |
| end_time | 结束时间 | Date | 否 | 关系结束的时间（为空表示持续中） |
| sync | 同步 | boolean | 否 | 默认 `false` |

> 关系可随时间变化：如恋人分手后变为仇人，应建两条 relation 边，分别标记不同的时间区间。

---

### involved — 人物参与事件 `N:N`

- **方向**：`Character → Event`

| 属性 | 中文 | 类型 | 必填 | 说明 |
|------|------|------|------|------|
| role | 角色 | string | 是 | 如"当事人""目击者""受害者""施害者""参与者" |
| detail | 详情 | string | 否 | |
| sync | 同步 | boolean | 否 | 默认 `false` |

---

### occurred_at — 事件发生地点 `N:1`

- **方向**：`Event → Location`

| 属性 | 中文 | 类型 | 必填 | 说明 |
|------|------|------|------|------|
| detail | 详情 | string | 否 | 如"跳江地点""约会地点" |
| sync | 同步 | boolean | 否 | 默认 `false` |

---

### at — 人物—地点 `N:N`

- **方向**：`Character → Location`

| 属性 | 中文 | 类型 | 必填 | 说明 |
|------|------|------|------|------|
| type | 关联类型 | string | 是 | 如"居住""前往""工作" |
| detail | 详情 | string | 否 | |
| start_time | 开始时间 | Date | 否 | 关联开始的时间 |
| end_time | 结束时间 | Date | 否 | 关联结束的时间（为空表示持续中） |
| sync | 同步 | boolean | 否 | 默认 `false` |

---

### link — 信息关联 `N:N`

- **方向**：`Character / Event / Location → Info`
- **限制**：仅叙事三大基础实体（Character、Event、Location）可关联 Info。

| 属性 | 中文 | 类型 | 必填 | 说明 |
|------|------|------|------|------|
| type | 关联类型 | string | 是 | 如"涉及""因果" |
| detail | 详情 | string | 否 | |
| time | 时间 | Date | 否 | 信息关联发生的时间 |
| sync | 同步 | boolean | 否 | 默认 `false` |

**特殊规则**：`type=因果` 时仅用于 `Info → Info`，表示原因→结果。

---

### evt_relation — 事件关联 `N:N`

- **方向**：`Event → Event`

| 属性 | 中文 | 类型 | 必填 | 说明 |
|------|------|------|------|------|
| type | 关联类型 | enum | 是 | `因果` / `先后` / `包含` |
| detail | 详情 | string | 否 | |
| sync | 同步 | boolean | 否 | 默认 `false` |

**type 方向语义**：`因果` = 前因→后果；`先后` = 时间顺序；`包含` = 大事件→子事件

---

### presents — 事件触发选择 `N:N`

- **方向**：`Event → Choice`

| 属性 | 中文 | 类型 | 必填 | 说明 |
|------|------|------|------|------|
| sync | 同步 | boolean | 否 | 默认 `false` |

> 某事件播放到此呈现选择。事件是源头（上游），选择由事件触发（下游），符合全局上游→下游。

### option — 选项导向后续 `N:N`

- **方向**：`Choice → Event`

| 属性 | 中文 | 类型 | 必填 | 说明 |
|------|------|------|------|------|
| label | 选项文本 | string | 是 | 玩家看到的选项：`再想想` / `跳江` / `选苏晓禾` |
| leads_to_ending | 导向结局 | boolean | 否 | 默认 `false`；`true` 表示该选项进入结局 |
| detail | 详情 | string | 否 | |
| sync | 同步 | boolean | 否 | 默认 `false` |

> 选择是因（上游），选完进入的事件是果（下游）。事件流嵌入：`Event -presents-> Choice -option-> Event`，Choice 作为分叉点嵌在事件链中间。

**Choice 与 evt_relation 的分工**：
- `evt_relation`（Event→Event）：事件链内部的因果 / 先后 / 时序串联。
- `Choice + presents + option`：管「在哪选择、选项导向哪条分支」，是分叉发源点。
- 分支点原先靠 `evt_relation{type:包含}` + title 文案后缀（「（分支A）」「BE」）hack，现由 `option` 边承载分支语义；主线 `先后 / 因果` 不受影响。

## ID 规则

所有节点使用雪花算法 Base62 编码作为 `id` 属性值（如 `Nv93TkkkgC`），全局唯一，无前缀。由 `.claude/scripts/snowflake_base62.py` 生成。

生成命令：
```bash
python "${CLAUDE_SKILL_DIR}/../../scripts/snowflake_base62.py" -n 1 -q
```

引用已有节点时，通过名称从数据库查询：
```cypher
MATCH (c:Character) WHERE c.name='角色名' RETURN c.id AS id
MATCH (e:Event) WHERE e.title='事件标题' RETURN e.id AS id
MATCH (s:Location) WHERE s.name='场景名' RETURN s.id AS id
MATCH (i:Info) WHERE i.title='信息标题' RETURN i.id AS id
MATCH (ch:Choice) WHERE ch.name='选择名' RETURN ch.id AS id
```
