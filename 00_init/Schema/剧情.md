## 章节编排（Chapter + Section + 产物链）图节点

> galgame 运行时剧本的**编排设计层锚点**。一章（Chapter）由若干节（Section）组成，一节统合若干 Scene。Chapter 只存章级编排信息（标题/序号/全章概要/分支骨架）；Section 是**纯编排容器**（节序/标题/概要，**无 status**），提纲/定稿/配音三种产物各自独立为节点，经 `has_outline`/`produces` 链式相连（sync 级联：改上游自动作废下游）。对话内容不入图——逐句对话存于创作区 `台词.jsonl`（JSONL 逐句一行，见 [剧本.md](../../.claude/skills/chapter-dialoguer/references/剧本.md)，发布时由 publisher 投影合并各节、转换为章 JSON；行级音频审批状态也在该文件行内）。运行时只读章 JSON，图作设计/编排/依赖追踪层。

### 章节（Chapter）

最小粒度：一个剧本章节文件对应的**章级编排单元**。结构段在此层完成（统一规划分节 + 全章情感弧）。

| 字段 | 中文 | 类型 | 必填 | 示例 |
|------|------|------|------|------|
| id | 编号 | string | 是 | snowflake Base62 |
| title | 标题 | string | 是 | `新皮肤·Day0` |
| chapter_no | 章节序号 | int | 是 | `1` |
| summary | 概要 | string | 否 | 本章叙事范围一句话（时间/地点/核心事件），编剧的创作纲要 |
| branch_summary | 分支骨架 | string | 否 | 主线/分支/结局简述（如「主线跳江未遂→BE跳下/TE生还」） |
| brief_path | 设计简报路径 | string | 否 | `25_剧本/chapter<NN>_<章概述>/设计简报.md`（structurer 产出；dashboard 结构审渲染简报全文） |
| status | 流程状态 | int | 否 | `0` |

**status 枚举**（章级结构段，一道审批）：`0` 待编排 → `10` 结构待审（structurer 生产完成**直写**，无 submit 步）→ `11` 结构已批。驳回归 `0`，作废 `-1`。规则在 [55_dashboard/core/status.py](../../55_dashboard/core/status.py) 的 `NODE_STATUS` 显式定义（Chapter completion=11）。

> `Chapter.status==11` 只代表「结构已批，进入节级生产」；**章真正可发布 = `Chapter.status==11` AND 全部节产物就绪（各节 SecOutline=1 ∧ SecScript=11 ∧ LineAudio=11）AND 所需立绘全 11**（由 plot-design / dashboard 显式判断，非 Chapter 的 status 字段）。

### 节（Section）

最小粒度：章节内一节对话的**节级编排容器**。一节统合若干 Scene，经 `has_outline` 挂提纲、提纲经 `produces` 链出定稿与配音。**纯编排节点，无 status 字段、无产物路径**（产物挂在 SecOutline/SecScript/LineAudio 三个节点上）。

| 字段 | 中文 | 类型 | 必填 | 示例 |
|------|------|------|------|------|
| id | 编号 | string | 是 | snowflake Base62 |
| section_no | 节序号 | int | 是 | `0`（章内从 0 起；排序权威 + 文件名 `<MM>` 来源） |
| title | 标题 | string | 是 | `酒店清晨` |
| summary | 概要 | string | 否 | 本节戏剧职责（来自 structurer 分节规划） |

### 提纲（SecOutline）

最小粒度：一节的**节级提纲产物节点**（`Section -[has_outline]-> SecOutline`，1:1）。由 `chapter-outliner` 兜底 MERGE 创建并写入。

| 字段 | 中文 | 类型 | 必填 | 示例 |
|------|------|------|------|------|
| id | 编号 | string | 是 | snowflake Base62 |
| name | 名称 | string | 是 | `<节标题>提纲` |
| outline_path | 提纲路径 | string | 否 | `25_剧本/chapter01_新皮肤/sec00_酒店清晨/outline.md`（提纲段产出 Markdown，定稿段读它填 lines） |
| description | 概要 | string | 否 | 简短描述 |
| status | 流程状态 | int | 否 | `0` |

**status 枚举**（数据节点，无审批）：`0` 待提纲 → `1` 提纲就绪。作废 `-1`。`NODE_STATUS` 中 SecOutline completion=1。

### 定稿（SecScript）

最小粒度：一节的**节级定稿产物节点**（`SecOutline -[produces]-> SecScript`，1:1）。由 `chapter-dialoguer` 兜底 MERGE 创建并写入。

| 字段 | 中文 | 类型 | 必填 | 示例 |
|------|------|------|------|------|
| id | 编号 | string | 是 | snowflake Base62 |
| name | 名称 | string | 是 | `<节标题>定稿` |
| script_path | 定稿路径 | string | 否 | `25_剧本/chapter01_新皮肤/sec00_酒店清晨/台词.jsonl`（定稿段产出 JSONL 逐句一行；publisher 投影合并各节为章 JSON） |
| description | 概要 | string | 否 | 简短描述 |
| status | 流程状态 | int | 否 | `0` |

**status 枚举**（一道定稿审）：`0` 待定稿 → `1` 草稿（dialoguer 草稿模式写，未提审）→ `10` 定稿待审（dialoguer 默认**直写**，无 submit 步）→ `11` 定稿已批。驳回归 `0`，作废 `-1`。**人工微调回路**：用户直接编辑 `台词.jsonl` 改单句后，dashboard「重新提交审批」`0/1/11→10`（不经 dialoguer，手改不丢；同回调把 LineAudio 置 `-1`，重配时 stale 机制只重做被改句）。`NODE_STATUS` 中 SecScript completion=11。

### 配音（LineAudio）

最小粒度：一节的**节级配音产物节点**（`SecScript -[produces]-> LineAudio`，1:1）。由 `section-voice-publisher` 兜底 MERGE 创建并写入；wav 母带/运行时副本按 voice key 落盘（见 [15_声音/README.md](../../15_声音/README.md)），节点只承载状态。

| 字段 | 中文 | 类型 | 必填 | 示例 |
|------|------|------|------|------|
| id | 编号 | string | 是 | snowflake Base62 |
| name | 名称 | string | 是 | `<节标题>配音` |
| description | 概要 | string | 否 | 简短描述（如各角色 wav 数） |
| status | 流程状态 | int | 否 | `0` |

**status 枚举**（一道逐句音频审）：`0` 待配音 → `10` 逐句审中（voice-publisher **直写**，无 submit 步）→ `11` 已批。驳回归 `0`（重配，台词不变），作废 `-1`。`NODE_STATUS` 中 LineAudio completion=11。

> **行级三态（非图字段）**：每条 say 行的 `audio.status ∈ {pending, approved, rejected}` 存于 `台词.jsonl` 行内（audio 对象另含 key/emotion/attempts/text_sha1——emotion 为配音期判别结果，text_sha1 判「台词改了没」）。节级 `10→11` 的 gate = 全部含 audio 的 say 行 approved 且无 rejected；单句驳回由 dashboard 写回行状态 + deeplink 唤起 plot-design 只重做该句。

> 创作流程（产物链，由五个 skill 推进）：
> - **结构段·章级**（`chapter-structurer`）：建 Chapter + 规划分节 + 建 Section（纯编排，无 status）+ `has_section`/`contains` 边 → Chapter `10` 结构待审（直写，无 submit 步）→ dashboard approve `11` 结构已批。
> - **提纲段·节级**（`chapter-outliner`，参数 section_id）：读章级设计简报 + 本节 Scene，产节级提纲 → 兜底建 SecOutline 节点（`Section-[:has_outline]->SecOutline`），写 `outline_path` + `1` 提纲就绪（**无审批**）。
> - **定稿段·节级**（`chapter-dialoguer`，参数 section_id）：读章级简报 + 本节提纲 → 产 `台词.jsonl`（JSONL 逐句一行，say 四字段无 emotion）+ 跑 `validate_chapter.py`（行级校验 + 投影 schema）+ 兜底建 BgmTrack/立绘缺口 → 兜底建 SecScript 节点（`SecOutline-[:produces]->SecScript`），写 `script_path` + `10` 定稿待审 → dashboard approve `11` 定稿已批（人工微调：直接改文件 + 「重新提交审批」0/1/11→10）。
> - **配音段·节级**（`section-voice-publisher`，参数 section_id）：定稿已批（SecScript=11）后挑行（missing/rejected/stale）克隆 TTS + **判别 emotion** + bind-audio 写行级 audio → 兜底建 LineAudio 节点（`SecScript-[:produces]->LineAudio`），写 `10` → dashboard 逐句音频审（行级三态，全 approved 后节级 approve `11`）。
> - **BGM·场景级**（`bgm-designer`，用户直触不进编排）：dialoguer 兜底建 BgmTrack(0) 后，产音乐描述文字 → 用户手动生成 wav 归档 `13_音乐/<name>.wav` → `2`。
> - **发布·章级**（`chapter-publisher`）：全章各节产物就绪（SecOutline=1 ∧ SecScript=11 ∧ LineAudio=11）时，投影合并各节 台词.jsonl 为单一章 JSON（演出注入：portrait 整键 + BGM）发布到 `99_game/`。
>
> **节完成**（派生判断，非字段）= SecOutline=1 ∧ SecScript=11 ∧ LineAudio=11。

### 边

#### has_section — 章节包含节 `1:N`

- **方向**：`Chapter → Section`

| 属性 | 中文 | 类型 | 必填 | 说明 |
|------|------|------|------|------|
| sync | 同步 | boolean | 否 | 默认 `true`（组成关系：章愿景变更 → 节作废重做） |

> Section 是 Chapter 的独占组成（一节只属一章）。人改 Chapter 属性时，沿 `sync=true` 出边把所有可达 Section 及其产物链（SecOutline→SecScript→LineAudio）重置为 `-1`（作废重做）。Section 的排序权威是 `section_no` 字段，不在边上另存 order。

#### has_outline — 节拥有提纲 `1:1`

- **方向**：`Section → SecOutline`

| 属性 | 中文 | 类型 | 必填 | 说明 |
|------|------|------|------|------|
| sync | 同步 | boolean | 否 | 默认 `true`（节编排属性变更 → 提纲及其下游全作废重做） |

> 一节一份提纲，由 `chapter-outliner` 兜底 MERGE 创建。编辑已就绪的 SecOutline 属性时，沿 `produces` 链把 SecScript/LineAudio 重置为 `-1`（改提纲 → 定稿/配音作废）。

#### produces — 提纲产出定稿 / 定稿产出配音 `1:1`

- **方向**：`SecOutline → SecScript`、`SecScript → LineAudio`（产物链，各 1:1）

| 属性 | 中文 | 类型 | 必填 | 说明 |
|------|------|------|------|------|
| sync | 同步 | boolean | 否 | 默认 `true`（上游产物变更 → 下游作废重做） |

> 链式级联：`SecOutline -[:produces]-> SecScript -[:produces]-> LineAudio`。改提纲 → 定稿+配音 `-1`；改定稿 → 配音 `-1`（台词变了 audio 的 text_sha1 失配，stale 机制只重做被改句）。**审批互不牵连**：驳回 SecScript 只重做 SecScript，SecOutline 不动。

#### contains — 节包含场景 `N:M`

- **方向**：`Section → Scene`

| 属性 | 中文 | 类型 | 必填 | 说明 |
|------|------|------|------|------|
| order | 序号 | int | 否 | 该场景在本节 scene-block 序列中的首次出现位置（JSON 的完整序列为运行时权威） |
| sync | 同步 | boolean | 否 | 默认 `false`（编排引用，不级联） |

> 节编排引用其用到的 Scene（Scene 已由 `Location -[has_scene]-> Scene` 存在）。一个 Scene 可被多个 Section / 多个 Chapter 引用。同一 Scene 在一节内重复出现时 MERGE 合为一条边，完整序列以 台词.jsonl/章 JSON 为权威。

#### depicts — 场景引用立绘设计图 `N:N`

- **方向**：`Scene → IllusDesign`

| 属性 | 中文 | 类型 | 必填 | 说明 |
|------|------|------|------|------|
| sync | 同步 | boolean | 否 | 默认 `false`（引用边，不级联） |

> 表示「该场景的剧本需要此着装的立绘可用」。`chapter-dialoguer` 据剧本 `say` 指令的 `<who>.<portrait>` 引用，按场景事件 wears（兜底取角色默认着装）选定 IllusDesign 后创建此边（同 Scene 同 IllusDesign 经 MERGE 去重）。**变体级缺口跟踪走 expands_to**：为每个被引用的变体兜底建 `StandingIllustration(status=0)` + `IllusDesign -[:expands_to]-> stand` + `LanguageStyle -[:ref_style]-> stand`。同一 IllusDesign 被多 Scene 引用时变体池共用（出图按 IllusDesign 级一次出多场景用）。`plot-design` agent 沿 `Scene -[:depicts]-> IllusDesign -[:expands_to]-> stand` 两跳枚举变体，对每个 `status≠11` 的 stand 直调 `char-stand-designer <stand_id>` 推进出图——立绘调用已从 `char-design` 剥离至 `plot-design`（按需出图，避免为未被引用的变体浪费 API）。
