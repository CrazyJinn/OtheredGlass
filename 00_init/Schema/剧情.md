## 章节编排（Chapter）图节点

> galgame 运行时剧本的**编排设计层锚点**。Chapter 在图中只存编排信息（标题/序号/场景顺序/分支骨架摘要），对话内容不入图——完整逐句对话存于创作区剧本 YAML（见 [剧本.md](../剧本.md)，发布时由 publisher 转 JSON）。运行时只读 JSON，图作设计/编排/依赖追踪层。

### 章节（Chapter）

最小粒度：一个剧本章节文件对应的编排单元。

| 字段 | 中文 | 类型 | 必填 | 示例 |
|------|------|------|------|------|
| id | 编号 | string | 是 | snowflake Base62 |
| title | 标题 | string | 是 | `新皮肤·Day0` |
| chapter_no | 章节序号 | int | 是 | `1` |
| script_path | 剧本路径 | string | 否 | `25_剧本/chapter01_新皮肤.yaml`（创作区定稿；publisher 发布时转换为 `99_game/data/chapters/<同名>.json`） |
| outline_path | 提纲路径 | string | 否 | `25_剧本/chapter01_新皮肤.outline.yaml`（提纲段产出，定稿段读它填 lines） |
| summary | 概要 | string | 否 | 本章叙事范围一句话（时间/地点/核心事件），编剧的创作纲要 |
| branch_summary | 分支骨架 | string | 否 | 主线/分支/结局简述（如「主线跳江未遂→BE跳下/TE生还」） |
| status | 流程状态 | int | 否 | `0` |

**status 枚举**（三段式，两道审批）：`0` 待编排 → `1` 结构就绪 → `10` 结构待审 → `11` 结构已批 → `20` 提纲就绪 → `30` 定稿待审 → `31` 定稿已批。驳回归 `0`（结构段）/ `20`（定稿段），作废 `-1`。规则在 [55_dashboard/core/status.py](../../55_dashboard/core/status.py) 的 `NODE_STATUS` 显式定义（completion=31）。

> Chapter 创作拆为三段，由三个 skill 串行推进（结构段 + 定稿段各一道审批）：
> - **结构段**（`chapter-structurer`）：建 Chapter + `contains` 边统合 Scene → `1` 结构就绪 → dashboard submit `10` 结构待审 → approve `11` 结构已批。
> - **提纲段**（`chapter-outliner`）：产提纲 JSON（`outline_path`）→ `20` 提纲就绪（**无审批**）。
> - **定稿段**（`chapter-dialoguer`）：读提纲填细节对话 + 跑 `validate_chapter.py` → `30` 定稿待审 → dashboard approve `31` 定稿已批（章节完成，可发布）。

### 边

#### contains — 章节包含场景 `N:M`

- **方向**：`Chapter → Scene`

| 属性 | 中文 | 类型 | 必填 | 说明 |
|------|------|------|------|------|
| order | 序号 | int | 否 | 该场景在章节 scene-block 序列中的首次出现位置（JSON 的完整序列为运行时权威） |
| sync | 同步 | boolean | 否 | 默认 `false`（编排引用，不级联） |

> 章节编排引用其用到的 Scene（Scene 已由 `Location -[has_scene]-> Scene` 存在）。一个 Scene 可被多个 Chapter 引用。同一 Scene 在一章内重复出现时，MERGE 合为一条边，完整序列以剧本（YAML/JSON）为权威。

#### depicts — 场景引用立绘 `N:N`

- **方向**：`Scene → StandingIllustration`

| 属性 | 中文 | 类型 | 必填 | 说明 |
|------|------|------|------|------|
| sync | 同步 | boolean | 否 | 默认 `false`（引用边，不级联） |

> 表示「该场景的剧本需要此立绘变体可用」。`chapter-dialoguer` 据剧本 `say` 指令的 `<who>.<portrait>` 创建此边；若目标 StandingIllustration 不存在，chapter-dialoguer 兜底建节点（`status=0`）+ `expands_to`/`ref_style` 边。这些缺口节点由 `plot-design` agent 按 depicts 引用直调 `char-stand-designer <stand_id>` 推进出图——立绘调用已从 `char-design` 剥离至 `plot-design`（按需出图，避免为未被引用的变体浪费 API）。
