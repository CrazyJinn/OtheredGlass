# 04 剧情

> 叙事自增长层：`nrt-narrative-grower` 分析叙事图缺口 → 生成创意草案 → 审批 → apply 写回叙事基础层。
> 草案以 **Markdown 文件**形式存于 `02_剧情数据/`，**不写入图数据库**。与 [叙事基础.md](叙事基础.md)（事实层）、[角色美术.md](角色美术.md) 互补。

---

## 概述

剧情层目前定义一类产物——**叙事草案（Narrative Draft，Markdown 文件）**，承载 `nrt-narrative-grower` 的 analyze→generate→apply 闭环。草案**不作为图节点存在**：流程状态（status / applied_at 等）存在 MD 文件的 YAML frontmatter，创意正文与分析存在 Markdown 正文。

**status 语义（草案 frontmatter）**：`10` 待审 / `11` 批准 / `0` 驳回 / `-1` 作废。

> **applied 用独立字段，不占 status 值**：apply 成功后写 frontmatter `applied_at`（非空 = 已应用），保持 status 取值集合稳定。

生命周期：`generate`（skill 侧，写 `02_剧情数据/<日期_概述>.md`，frontmatter `status=10`）→ **人工审批**（手动把 frontmatter `status` 由 `10` 改 `11` / 驳回改 `0`）→ `apply`（skill 侧，`status=11` 后从 MD 正文提取基础节点写回叙事基础层 + 回写 frontmatter `applied_at`）。

---

## 产物：叙事草案（`02_剧情数据/<日期_概述>.md`）

每次 analyze→generate 产出一个 `.md` 文件，**文件名 = `YYYY-MM-DD_<概述>.md`**（日期取自 `created_at`，概述取自标题核心主题，清洗 Windows 非法字符）。frontmatter 的 snowflake `id` 仅作稳定唯一锚点，不参与文件名。apply 后从正文提取为基础节点写回。

### 文件结构

YAML frontmatter（流程状态）+ Markdown 正文（创意草案 + 分析）：

```markdown
---
id: <draft_id>
title: '<标题>'
status: 10              # 10 待审 / 11 批准 / 0 驳回 / -1 作废
created_at: '<ISO 时间戳>'
applied_at: null        # null=未应用；apply 成功后写 ISO 时间（应用标记）
applied_node_ids: ''    # apply 写入的基础节点 id，分号分隔
---

# <标题>

<创意草案正文：拟增角色/事件/地点/信息及关系，apply 据此提取>

## 分析依据（analyze）

<人类可读摘要；growth_opportunities 的 summary/suggestions/details 可作参考置于正文>
```

### frontmatter 字段

| 字段 | 中文 | 类型 | 必填 | 说明 |
|------|------|------|------|------|
| id | 编号 | string | 否 | snowflake Base62，稳定唯一锚点（**非文件名**；文件名=日期+概述） |
| title | 标题 | string | 是 | 草案标题 |
| status | 流程状态 | int | 否 | `10` 待审 / `11` 批准 / `0` 驳回 / `-1` 作废 |
| created_at | 创建时间 | string | 否 | ISO 时间（generate 写入） |
| applied_at | 应用时间 | string | 否 | null=未应用；apply 成功后写 ISO 时间（**应用标记**） |
| applied_node_ids | 应用节点 | string | 否 | apply 写入的基础节点 id，分号分隔 |

### 正文语义

| 正文 | 中文 | 说明 |
|------|------|------|
| 草案正文 | 创意内容 | 自然语言，含拟增角色/事件/地点/信息及关系；apply 据此提取 |
| 分析依据 | analyze 摘要 | growth_opportunities 的人类可读摘要（可选附 JSON） |

**status 枚举**：`10` 待审 → `11` 批准 →（apply 回写 `applied_at`）；`10` → `0` 驳回。

## 边

草案**不建任何图边**：

- 草案本身不是图节点，与既有实体之间没有边（无 `proposed_for`）。
- apply 后产生的基础节点之间，用叙事基础层的 6 种边（relation / involved / occurred_at / at / link / evt_relation）自连，保持基础层纯净。
- 溯源用 frontmatter 的 `applied_node_ids` 字段（apply 写入的节点 id 列表）。

---

## 文件名与 ID

- **文件名**：`YYYY-MM-DD_<概述>.md`（日期取自 `created_at`，概述取自标题核心主题，清洗 Windows 非法字符）——草案的用户面标识，apply 据此 Glob 定位文件。
- **frontmatter `id`**：snowflake Base62，全局唯一无前缀（同叙事基础层），仅作稳定唯一锚点（文件改名/复制后仍可追溯），**不参与文件名**：

```bash
python "${CLAUDE_SKILL_DIR}/../../scripts/snowflake_base62.py" -n 1 -q
```
