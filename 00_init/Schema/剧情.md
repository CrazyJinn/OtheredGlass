## 章节编排（Chapter + Section + 产物链）图节点

> galgame 运行时剧本的**编排设计层锚点**。一章（Chapter）由若干节（Section）组成，一节统合若干 Scene。Chapter 只存章级编排信息（标题/序号/全章概要/分支骨架）；Section 是**纯编排容器**（节序/标题/概要，**无 status**），提纲/定稿/配音三种产物各自独立为节点，经 `has_outline`/`produces` 链式相连（sync 级联：改上游自动作废下游）。**对话逐句入图**：定稿（台词.md，人读/人改的唯一界面格式）审批通过后由 section-voice-publisher 拆分为逐句 `LineAudio` 节点（`SecScript -[:produces {order}]-> LineAudio`，1:N，大间距排序）并配音；行级音频审批状态即行节点 `status`。发布时 publisher 直接从图投影合并各节为章 JSON（运行时唯一消费物），`台词.jsonl` 已停产（历史文件留在创作区，链路不再读取）。

### 章节（Chapter）

最小粒度：一个剧本章节文件对应的**章级编排单元**。结构段在此层完成（统一规划分节 + 全章情感弧）。

| 字段 | 中文 | 类型 | 必填 | 示例 |
|------|------|------|------|------|
| id | 编号 | string | 是 | snowflake Base62 |
| title | 标题 | string | 是 | `新皮肤·Day0` |
| chapter_no | 章节序号 | int | 是 | `1` |
| summary | 概要 | string | 否 | 本章叙事范围一句话（时间/地点/核心事件），编剧的创作纲要 |
| branch_summary | 分支骨架 | string | 否 | 主线/分支/结局简述（如「主线跳江未遂→BE跳下/TE生还」） |
| brief_path | 设计简报路径 | string | 否 | `25_剧本/chapter<NN>_<章概述>/设计简报.md`（structurer 产出；dashboard 结构审渲染简报全文） |
| status | 流程状态 | int | 否 | `0` |

**status 枚举**（章级结构段，一道审批）：`0` 待编排 → `10` 结构待审（structurer 生产完成**直写**，无 submit 步）→ `11` 结构已批。驳回归 `0`，作废 `-1`。规则在 [55_dashboard/core/status.py](../../55_dashboard/core/status.py) 的 `NODE_STATUS` 显式定义（Chapter completion=11）。

> `Chapter.status==11` 只代表「结构已批，进入节级生产」；**章真正可发布 = `Chapter.status==11` AND 全部节产物就绪（各节 SecOutline=1 ∧ SecScript=11 ∧ LineAudio=11）AND 所需立绘全 11**（由 plot-design / dashboard 显式判断，非 Chapter 的 status 字段）。

### 节（Section）

最小粒度：章节内一节对话的**节级编排容器**。一节统合若干 Scene，经 `has_outline` 挂提纲、提纲经 `produces` 链出定稿与配音。**纯编排节点，无 status 字段、无产物路径**（产物挂在 SecOutline/SecScript/LineAudio 三个节点上）。

| 字段 | 中文 | 类型 | 必填 | 示例 |
|------|------|------|------|------|
| id | 编号 | string | 是 | snowflake Base62 |
| section_no | 节序号 | int | 是 | `0`（章内从 0 起；排序权威 + 文件名 `<MM>` 来源） |
| title | 标题 | string | 是 | `酒店清晨` |
| summary | 概要 | string | 否 | 本节戏剧职责（来自 structurer 分节规划） |

### 提纲（SecOutline）

最小粒度：一节的**节级提纲产物节点**（`Section -[has_outline]-> SecOutline`，1:1）。由 `chapter-outliner` 兜底 MERGE 创建并写入。

| 字段 | 中文 | 类型 | 必填 | 示例 |
|------|------|------|------|------|
| id | 编号 | string | 是 | snowflake Base62 |
| name | 名称 | string | 是 | `<节标题>提纲` |
| outline_path | 提纲路径 | string | 否 | `25_剧本/chapter01_新皮肤/sec00_酒店清晨/outline.md`（提纲段产出 Markdown，定稿段读它填 lines） |
| description | 概要 | string | 否 | 简短描述 |
| status | 流程状态 | int | 否 | `0` |

**status 枚举**（数据节点，无审批）：`0` 待提纲 → `1` 提纲就绪。作废 `-1`。`NODE_STATUS` 中 SecOutline completion=1。

### 定稿（SecScript）

最小粒度：一节的**节级定稿产物节点**（`SecOutline -[produces]-> SecScript`，1:1）。由 `chapter-dialoguer` 兜底 MERGE 创建并写入。

| 字段 | 中文 | 类型 | 必填 | 示例 |
|------|------|------|------|------|
| id | 编号 | string | 是 | snowflake Base62 |
| name | 名称 | string | 是 | `<节标题>定稿` |
| script_path | 定稿路径 | string | 否 | `25_剧本/chapter01_新皮肤/sec00_酒店清晨/台词.md`（人读/人改的唯一界面格式，Markdown；审批与拆分均以它为准） |
| description | 概要 | string | 否 | 简短描述 |
| status | 流程状态 | int | 否 | `0` |

**status 枚举**（一道定稿审）：`0` 待定稿 → `1` 草稿（dialoguer 草稿模式写，未提审）→ `10` 定稿待审（dialoguer 默认**直写**，无 submit 步）→ `11` 定稿已批。驳回归 `0`，作废 `-1`。**人工微调回路**：用户直接编辑 `台词.md` 改单句后，dashboard「重新提交审批」`0/1/11→10`（不经 dialoguer，**只改 sc status、不动行节点**）；重批后重拆，text_sha1 匹配的行原样保留审批结果，只有被改句置 `0` 重配——手改不丢。`NODE_STATUS` 中 SecScript completion=11。

### 台词行（LineAudio）

最小粒度：**一句台词/旁白/结构行**（`SecScript -[produces {order}]-> LineAudio`，1:N）。定稿审批通过（SecScript=11）后由 `section-voice-publisher` 第一步「拆分进图」幂等写入（`script_splitter.py` 对齐 台词.md 与已有行：新增建节点、修改沿用节点置 0、删除 DETACH DELETE、级联作废的未变句恢复）；节点 id（雪花）即**行身份**——voice key 末段，插入/删除行不影响其他行。wav 母带/运行时副本按 voice key 落盘（见 [15_声音/README.md](../../15_声音/README.md)）。

| 字段 | 中文 | 类型 | 必填 | 示例 |
|------|------|------|------|------|
| id | 编号 | string | 是 | snowflake Base62（= 行身份，voice key 末段） |
| name | 名称 | string | 是 | 行正文本身（= text；scene 行 = scene_block_id） |
| op | 行类型 | enum | 是 | `say` / `narrate` / `scene` / `label` / `ending`（choice 及配套 jump 暂不进图，建模后续设计） |
| who | 说话人 | string | 否 | say 行必填（Character.name 原名） |
| portrait | 表情变体 | string | 否 | say 行可选（拆分自 md `[表情]` 标注）；立绘缺口由 section-voice-publisher 据此兜底建（depicts/expands_to） |
| pos | 立绘位 | enum | 否 | `left` / `center` / `right`（拆分时定：沿用同场景块内该角色上一次 pos，缺省 left） |
| text | 台词原文 | string | 否 | md 拆分写入；投影字幕用；`text_sha1 = sha1(text)` 判「台词改了没」（对齐/stale 唯一依据） |
| tts_text | 配音变体 | string | 否 | 配音期 LLM 由原文产，**仅标点/停顿级修饰**（省略号/叹号/问号/破折号/逗号），**禁增删改汉字**——运行时字幕显示 text，变体发声须与字幕字面一致；**TTS 实际输入与情绪承载唯一通道**（Qwen3 Base clone 无 instruct 通道）；空=未配音；仅 say 行。变体不得写回 text（会破坏对齐）。强烈语气诉求（语气词/引导词）写进台词.md 原文（text 层，stale 自动重配），不在变体加字 |
| kind | 结局类型 | enum | 否 | **仅 op=ending 行**：`BE` / `TE` / `HE` / `NE` |
| scene_block_id | 场景块 | string | 否 | **仅 op=scene 行**：structurer 预分配的块 id（如 `s00_酒店`，章内唯一）；场景实体经 `stages` 边关联，行上不冗余存场景名/时段 |
| voice_key | 配音键 | string | 否 | `<char>-<chapter_stem>-<scene_block_id>-<行id>`，配音后写 |
| emotion | 情绪 | string | 否 | 配音期判别（12 词表）；图标注与筛选用，不进合成参数（情绪由 tts_text 承载） |
| attempts | 尝试次数 | int | 否 | 重配计数；`status=0 且 attempts>0` = 被驳回 |
| text_sha1 | 文本指纹 | string | 否 | sha1(text)，stale 判定依据 |
| status | 流程状态 | int | 否 | `0` |

**status 枚举**（行级音频审——台词文字已在 SecScript 定稿审完成，行 status **只代表音频**）：`0` 待配音/被驳回 → `10` 配完待审（voice-publisher **直写**，无 submit 步）→ `11` 已批。驳回归 `0`，作废 `-1`（sync 级联）。**非 say 行**（narrate/scene/label/ending，无音频语义）拆分即 `11`。**「节配音完成」**（派生判断）= 该节全部行 status=11；单句驳回由 dashboard 置 0 + deeplink 唤起 plot-design 只重配该句。

> **级联与恢复**：sync 级联（SecScript/上游属性变更）把该节全部行置 `-1`；重拆时 text_sha1 匹配且 wav 在的行恢复 `10`（音频复用不重配，保守进审），否则 `0`。人工微调回路（改 md → 重新提交审批）**不置行 -1**：重拆时未变句原样保留（含已批的 `11`），只有 text 变化句置 `0`——单句修改不丢。order 中点耗尽（上下差 <1）时全节重排，行 id/voice_key 不受影响。

> 创作流程（产物链，由五个 skill 推进）：
> - **结构段·章级**（`chapter-structurer`）：建 Chapter + 规划分节 + 建 Section（纯编排，无 status）+ `has_section`/`contains` 边 + 预分配全章 scene-block id → Chapter `10` 结构待审（直写，无 submit 步）→ dashboard approve `11` 结构已批。
> - **提纲段·节级**（`chapter-outliner`，参数 section_id）：读章级设计简报 + 本节 Scene，产节级提纲 → 兜底建 SecOutline 节点（`Section-[:has_outline]->SecOutline`），写 `outline_path` + `1` 提纲就绪（**无审批**）。
> - **定稿段·节级**（`chapter-dialoguer`，参数 section_id，**纯台词创作**）：读章级简报 + 本节提纲 → 产 `台词.md`（人读 Markdown，机器可解析）→ 兜底建 SecScript 节点（`SecOutline-[:produces]->SecScript`），写 `script_path` + `10` 定稿待审 → dashboard approve `11` 定稿已批（人工微调：直接改 md + 「重新提交审批」0/1/11→10）。
> - **配音段·节级**（`section-voice-publisher`，参数 section_id）：定稿已批（SecScript=11）后**拆分进图**（script_splitter.py 对齐 台词.md → 逐句 LineAudio 节点 + `produces{order}`）→ **兜底建立绘缺口**（据行 portrait 引用建 depicts 边 + StandingIllustration 变体节点）→ 挑行（say 行 status=0）+ **判别 emotion + 产 tts_text 变体** + Qwen3 Base Voice Clone 逐句克隆（voice_clone_runner publish）+ bind 写行节点（`voice_key/emotion/tts_text/status=10`）→ dashboard 逐句音频审（行 status 0→10→11）。
> - **BGM·场景级**（`bgm-designer`，**scene-design agent 编排**）：scene-design 发现 Scene 的 BgmTrack 缺口（无节点或 status∈{-1,0}）时调 bgm-designer（自行兜底建 BgmTrack(0)+has_bgm）→ 产音乐描述文字 → 用户手动生成 wav 归档 `13_音乐/<name>.wav` → `2`。plot-design 不查不调 BgmTrack。
> - **发布·章级**（`chapter-publisher`）：全章各节产物就绪（各节 SecOutline=1 ∧ SecScript=11 ∧ 该节全部行 LineAudio=11）时，**从图投影**各节行（produces.order 排序）合并为单一章 JSON（演出注入：portrait 整键 + BGM）发布到 `99_game/`。
>
> **节完成**（派生判断，非字段）= SecOutline=1 ∧ SecScript=11 ∧ 该节全部 LineAudio 行=11。

### 边

#### has_section — 章节包含节 `1:N`

- **方向**：`Chapter → Section`

| 属性 | 中文 | 类型 | 必填 | 说明 |
|------|------|------|------|------|
| sync | 同步 | boolean | 否 | 默认 `true`（组成关系：章愿景变更 → 节作废重做） |

> Section 是 Chapter 的独占组成（一节只属一章）。人改 Chapter 属性时，沿 `sync=true` 出边把所有可达 Section 及其产物链（SecOutline→SecScript→LineAudio）重置为 `-1`（作废重做）。Section 的排序权威是 `section_no` 字段，不在边上另存 order。

#### has_outline — 节拥有提纲 `1:1`

- **方向**：`Section → SecOutline`

| 属性 | 中文 | 类型 | 必填 | 说明 |
|------|------|------|------|------|
| sync | 同步 | boolean | 否 | 默认 `true`（节编排属性变更 → 提纲及其下游全作废重做） |

> 一节一份提纲，由 `chapter-outliner` 兜底 MERGE 创建。编辑已就绪的 SecOutline 属性时，沿 `produces` 链把 SecScript/LineAudio 重置为 `-1`（改提纲 → 定稿/配音作废）。

#### produces — 提纲产出定稿 `1:1` / 定稿产出台词行 `1:N`

- **方向**：`SecOutline → SecScript`（1:1）、`SecScript → LineAudio`（**1:N**，逐句行）

| 属性 | 中文 | 类型 | 必填 | 说明 |
|------|------|------|------|------|
| order | 排序 | int | 否 | **仅 SecScript→LineAudio 段**：行在节内的顺序。大间距数字——初始 `(i+1)×1000`；两句之间插入新行取 `(上句 order + 下句 order) ÷ 2`（整除）；中点差 <1 时全节重排（order 仅为排序键不进 voice key，重排安全） |
| sync | 同步 | boolean | 否 | 默认 `true`（上游产物变更 → 下游作废重做） |

> 链式级联：`SecOutline -[:produces]-> SecScript -[:produces]-> LineAudio(×N)`。改提纲 → 定稿 `-1` + 全部行 `-1`；改定稿 → 全部行 `-1`（重拆时 text_sha1 匹配且 wav 在的行恢复 `10`，只重配被改句）。**审批互不牵连**：驳回 SecScript 只重做 SecScript，SecOutline 不动；行级驳回只置该行 `0`。

#### stages — 场景块演出场景 `N:1`

- **方向**：`LineAudio(op=scene) → Scene`

| 属性 | 中文 | 类型 | 必填 | 说明 |
|------|------|------|------|------|
| sync | 同步 | boolean | 否 | 默认 `false`（引用边，不级联） |

> 场景块行（op=scene）指向其演出的 Scene 实体——块的时段投影时读 `Scene.time_of_day`（行上不冗余存场景名/时段）。同一 Scene 在一节内出现多次 = 多个 scene 行（各自的 scene_block_id），各自 stages 指向同一 Scene。场景美术链（has_bgm/depicts）以 Scene 为锚点，与本边解耦。

#### contains — 节包含场景 `N:M`

- **方向**：`Section → Scene`

| 属性 | 中文 | 类型 | 必填 | 说明 |
|------|------|------|------|------|
| order | 序号 | int | 否 | 该场景在本节 scene-block 序列中的首次出现位置（JSON 的完整序列为运行时权威） |
| sync | 同步 | boolean | 否 | 默认 `false`（编排引用，不级联） |

> 节编排引用其用到的 Scene（Scene 已由 `Location -[has_scene]-> Scene` 存在）。一个 Scene 可被多个 Section / 多个 Chapter 引用。同一 Scene 在一节内重复出现时 MERGE 合为一条边，完整序列以图行（produces.order + op=scene 行的 scene_block_id）/章 JSON 为权威。

#### depicts — 场景引用立绘设计图 `N:N`

- **方向**：`Scene → IllusDesign`

| 属性 | 中文 | 类型 | 必填 | 说明 |
|------|------|------|------|------|
| sync | 同步 | boolean | 否 | 默认 `false`（引用边，不级联） |

> 表示「该场景的剧本需要此着装的立绘可用」。`section-voice-publisher` 拆分进图后据图行（`LineAudio` say 行的 who+portrait 引用），按场景事件 wears（兜底取角色默认着装）选定 IllusDesign 后创建此边（同 Scene 同 IllusDesign 经 MERGE 去重）——台词.md 的 `[表情]` 标注在此变成图结构（chapter-dialoguer 纯台词创作，不建任何缺口）。**变体级缺口跟踪走 expands_to**：为每个被引用的变体兜底建 `StandingIllustration(status=0)` + `IllusDesign -[:expands_to]-> stand` + `LanguageStyle -[:ref_style]-> stand`。同一 IllusDesign 被多 Scene 引用时变体池共用（出图按 IllusDesign 级一次出多场景用）。`plot-design` agent 沿 `Scene -[:depicts]-> IllusDesign -[:expands_to]-> stand` 两跳枚举变体，对每个 `status≠11` 的 stand 直调 `char-stand-designer <stand_id>` 推进出图——立绘调用已从 `char-design` 剥离至 `plot-design`（按需出图，避免为未被引用的变体浪费 API）。
