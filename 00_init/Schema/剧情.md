## 章节编排（Chapter + Section）图节点

> galgame 运行时剧本的**编排设计层锚点**。一章（Chapter）由若干节（Section）组成，一节统合若干 Scene。Chapter 只存章级编排信息（标题/序号/全章概要/分支骨架），Section 存节级编排信息（节序/标题/节概要/提纲与定稿路径）。对话内容不入图——完整逐句对话存于创作区剧本 YAML（见 [剧本.md](../剧本.md)，发布时由 publisher 合并各节、转换为 JSON）。运行时只读 JSON，图作设计/编排/依赖追踪层。

### 章节（Chapter）

最小粒度：一个剧本章节文件对应的**章级编排单元**。结构段在此层完成（统一规划分节 + 全章情感弧）。

| 字段 | 中文 | 类型 | 必填 | 示例 |
|------|------|------|------|------|
| id | 编号 | string | 是 | snowflake Base62 |
| title | 标题 | string | 是 | `新皮肤·Day0` |
| chapter_no | 章节序号 | int | 是 | `1` |
| summary | 概要 | string | 否 | 本章叙事范围一句话（时间/地点/核心事件），编剧的创作纲要 |
| branch_summary | 分支骨架 | string | 否 | 主线/分支/结局简述（如「主线跳江未遂→BE跳下/TE生还」） |
| status | 流程状态 | int | 否 | `0` |

**status 枚举**（章级结构段，一道审批）：`0` 待编排 → `1` 结构就绪 → `10` 结构待审 → `11` 结构已批。驳回归 `0`，作废 `-1`。规则在 [55_dashboard/core/status.py](../../55_dashboard/core/status.py) 的 `NODE_STATUS` 显式定义（Chapter completion=11）。

> `Chapter.status==11` 只代表「结构已批，进入节级生产」；**章真正可发布 = `Chapter.status==11` AND 全部 Section `status==31`**（由 plot-design / dashboard 显式判断，非 Chapter 的 status 字段）。

### 节（Section）

最小粒度：章节内一节对话的**节级编排单元**，是提纲/定稿段的创作粒度。一节统合若干 Scene，对应一份节级提纲 YAML + 一份节级定稿 YAML。

| 字段 | 中文 | 类型 | 必填 | 示例 |
|------|------|------|------|------|
| id | 编号 | string | 是 | snowflake Base62 |
| section_no | 节序号 | int | 是 | `0`（章内从 0 起；排序权威 + 文件名 `<MM>` 来源） |
| title | 标题 | string | 是 | `酒店清晨` |
| summary | 概要 | string | 否 | 本节戏剧职责（来自 structurer 分节规划） |
| outline_path | 提纲路径 | string | 否 | `25_剧本/chapter01_新皮肤/sec00_酒店清晨/outline.yaml`（提纲段产出，定稿段读它填 lines） |
| script_path | 定稿路径 | string | 否 | `25_剧本/chapter01_新皮肤/sec00_酒店清晨/完整对话.yaml`（定稿段产出；publisher 合并各节为章 JSON） |
| status | 流程状态 | int | 否 | `0` |

**status 枚举**（节级提纲/定稿段，一道审批，**无结构审**）：`0` 待提纲 → `20` 提纲就绪 → `30` 定稿待审 → `31` 定稿已批。驳回归 `20`，作废 `-1`。`NODE_STATUS` 中 Section completion=31。

> 创作流程（混合粒度：结构段章级 + 提纲/定稿段节级，由四个 skill 推进）：
> - **结构段·章级**（`chapter-structurer`）：建 Chapter + 规划分节 + 建 Section + `has_section`/`contains` 边 → Chapter `1` 结构就绪 → dashboard submit `10` 结构待审 → approve `11` 结构已批。各 Section 初始 `status=0`。
> - **提纲段·节级**（`chapter-outliner`，参数 section_id）：读章级设计简报 + 本节 Scene，产节级提纲（`Section.outline_path`）→ Section `20` 提纲就绪（**无审批**）。
> - **定稿段·节级**（`chapter-dialoguer`，参数 section_id）：读章级简报 + 本节提纲填逐句对话 + 跑 `validate_chapter.py` → Section `30` 定稿待审 → dashboard approve `31` 定稿已批。
> - **发布·章级**（`chapter-publisher`）：全章各 Section 均 `31` 时，合并各节定稿 YAML 拍平为单一章 JSON 发布到 `99_game/`。

### 边

#### has_section — 章节包含节 `1:N`

- **方向**：`Chapter → Section`

| 属性 | 中文 | 类型 | 必填 | 说明 |
|------|------|------|------|------|
| sync | 同步 | boolean | 否 | 默认 `true`（组成关系：章愿景变更 → 节作废重做） |

> Section 是 Chapter 的独占组成（一节只属一章）。人改 Chapter 属性时，沿 `sync=true` 出边把所有可达 Section 重置为 `-1`（作废重做）。Section 的排序权威是 `section_no` 字段，不在边上另存 order。

#### contains — 节包含场景 `N:M`

- **方向**：`Section → Scene`

| 属性 | 中文 | 类型 | 必填 | 说明 |
|------|------|------|------|------|
| order | 序号 | int | 否 | 该场景在本节 scene-block 序列中的首次出现位置（JSON 的完整序列为运行时权威） |
| sync | 同步 | boolean | 否 | 默认 `false`（编排引用，不级联） |

> 节编排引用其用到的 Scene（Scene 已由 `Location -[has_scene]-> Scene` 存在）。一个 Scene 可被多个 Section / 多个 Chapter 引用。同一 Scene 在一节内重复出现时 MERGE 合为一条边，完整序列以剧本（YAML/JSON）为权威。

#### depicts — 场景引用立绘设计图 `N:N`

- **方向**：`Scene → IllusDesign`

| 属性 | 中文 | 类型 | 必填 | 说明 |
|------|------|------|------|------|
| sync | 同步 | boolean | 否 | 默认 `false`（引用边，不级联） |

> 表示「该场景的剧本需要此着装的立绘可用」。`chapter-dialoguer` 据剧本 `say` 指令的 `<who>.<portrait>` 引用，按场景事件 wears（兜底取角色默认着装）选定 IllusDesign 后创建此边（同 Scene 同 IllusDesign 经 MERGE 去重）。**变体级缺口跟踪走 expands_to**：为每个被引用的变体兜底建 `StandingIllustration(status=0)` + `IllusDesign -[:expands_to]-> stand` + `LanguageStyle -[:ref_style]-> stand`。同一 IllusDesign 被多 Scene 引用时变体池共用（出图按 IllusDesign 级一次出多场景用）。`plot-design` agent 沿 `Scene -[:depicts]-> IllusDesign -[:expands_to]-> stand` 两跳枚举变体，对每个 `status≠11` 的 stand 直调 `char-stand-designer <stand_id>` 推进出图——立绘调用已从 `char-design` 剥离至 `plot-design`（按需出图，避免为未被引用的变体浪费 API）。
