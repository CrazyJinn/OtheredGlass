# 声音

> 角色如何从文字变成声音——每个角色的基线音色设计（TTS 声音设计参数 + 可听参考音频）与场景背景音乐（BGM 资产链）。`Character → VoiceDesign` 经 `has_voice_design` 1:1 关联；`Scene → BgmTrack` 经 `has_bgm` 1:1 关联。基线音色确定后，整章所有台词复用同一参考音频。

> **命名消歧**：本 Schema 的 `VoiceDesign` 指**图节点**（角色声音设计）；Qwen3-TTS 的 `Qwen VoiceDesign` 指**TTS 模型**。全项目文档中模型一律带 `Qwen` 前缀，不与节点名混用。

---

## 定位

- **基线音色，非逐句音色**：每个角色一个 VoiceDesign（1:1）。不同情绪（调侃 / 沉吟 / 愤怒）由 Qwen3 Base Voice Clone 以 `tts_text` 配音变体承载（配音期判别的 `emotion` 仅作图标注与筛选，不进合成参数），不建情绪多维档案。
- **区别于 LanguageStyle**：`has_voice_style` 指向 LanguageStyle（**文字层**说话方式——词汇 / 节奏 / 口头禅），供 `chapter-dialoguer` 写对白；`has_voice_design` 指向 VoiceDesign（**声音层**音色设计——instruct / 参考音频），供 `section-voice-publisher` 节级配音。两者正交，**边名绝不混用**。
- **产物不进运行时图**：VoiceDesign 的 `ref_audio_path` 指向 `14_声音设计/<char>/` 的设计母带；逐句克隆的 wav 母带在 `15_声音/<char>/`，运行时副本由 `voice_bundler sync` 拷贝到 `99_game/assets/voices/`，`section-voice-publisher` 经 bind-graph 写行节点 `voice_key`、`chapter-publisher` 合并时带入章 JSON（voice_key 字段见 [剧情.md](剧情.md)）。

## 节点

### 声音设计（VoiceDesign）

每个角色一个。定义角色的基线音色——Qwen VoiceDesign 自然语言 instruct + 固化音色的参考音频。基线确定后整章台词复用同一 ref_audio（合成一次，GPU 密集步骤不重复）。

| 字段 | 中文 | 类型 | 必填 | 说明 |
|------|------|------|------|------|
| id | 编号 | string | 是 | snowflake Base62 |
| name | 名称 | string | 是 | `<角色名>声音设计` |
| instruct | 声音设计指令 | string | 否 | Qwen VoiceDesign 模型的 instruct 文本（年龄 / 性别 / 音色 / 气质 / 语速 / 尾音特征） |
| ref_text | 参考文本 | string | 否 | 固化音色用的参考句；**全角色统一通用长句**（54 字中性陈述，约 10~12 秒，覆盖翘舌/平舌/前后鼻音/复韵母）：`上午我把书桌上的三份文件整理好，然后把水杯和钥匙放进背包，中午在城南餐厅吃了一顿面，下午再准时把报告直接交给负责人。`（中性无性格预设，同句对比可辨频段/纹理差异；不直接对外） |
| ref_audio_path | 参考音频 | string | 否 | 参考音频相对路径 `14_声音设计/<char>/<char>_ref.wav`（多候选流程：dashboard 采用选中候选后固化的 24kHz 正式产物；下游 voice_clone_runner publish 以 24k 原生直接消费） |
| candidates_path | 候选清单 | string | 否 | 多候选流程 manifest 路径 `14_声音设计/<char>/candidates/candidates.json`；**非空表示 status=10 处于「候选待选」子态**（3 候选 ref 24k + 3×3 情绪试听 Qwen3 Base），dashboard 采用后该属性被删除 |
| clone_prompt_path | 克隆提示词 | string | 否 | **已废弃**（历史兼容保留）：早期路线的 `.pt` 落盘文件（先 Qwen Base 落盘期、后 CosyVoice3 期均不产出）；现行 Qwen3 Base Voice Clone 在合成时内存构建 clone prompt，不落盘 |
| description | 概要 | string | 否 | 简短描述音色气质（1-2 句） |
| status | 流程状态 | int | 否 | `0` |

**status 枚举**：`0` 待设计 → `1` instruct 完成（文本设计）→ `10` ref_audio 固化（可听，生产完成**即待审**）→ `11` 批准。`-1` 级联重置后重做；`2` 为历史兼容值（旧流程生产完成态，存量节点可经 dashboard 编辑器 submit 迁 `10`，skill 不再写 `2`）。

> **status=10 两态**（由 `candidates_path` 区分，status 值不变）：`candidates_path` 非空 = **候选待选**（3 个候选 ref 24k + 每候选 3 情绪试听已落盘 `14_声音设计/<char>/candidates/`，dashboard 审批中心逐候选试听后「采用」——固化为 `<char>_ref.wav` + 删除 candidates_path + 清理临时文件夹，status 保持 10）；空/缺 = **单 ref 待审**（走常规通过/驳回，存量节点零迁移）。

> **审批门**：音色好坏是连续主观判断，迭代仍靠「听一句不满意就改 instruct 重跑」；但为治理下游配音消耗（逐句克隆 GPU 密集），设置审批门——候选与试听产物固化落盘后 `char-voice-design` 直接写 `10`（待审，无 submit 步），dashboard 审批中心候选试听 →「采用」（收敛候选，status 仍 10）→ 通过 `11`（批准）/ 驳回回 `0`（重做）。**下游配音（section-voice-publisher）要求 `status=11`**。
>
> **`clone_prompt_path` 已废弃**：该字段属早期 Qwen Base clone 落盘 `.pt` 的路线，后被 CosyVoice3 `inference_instruct2` 替代（CosyVoice3 已废弃删除）；现行 Qwen3 Base Voice Clone 的 clone prompt 为运行时内存构建、不落盘。字段保留作历史兼容，`char-voice-design` 不写、`section-voice-publisher` 不读。

### 背景音乐（BgmTrack）

一个场景一首背景音乐（`Scene -[has_bgm]-> BgmTrack`，1:1）。**人工生成链**：`bgm-designer` skill 产出音乐描述文字（prompt）→ 用户在外部工具（Suno 类）手动生成 .wav → 归档到预制路径 `13_音乐/<name>.wav` → 状态置 2。台词文件不写 BGM——发布时由 chapter-publisher 查 `has_bgm` 注入章 JSON scene-block 的 bgm 字段（`generate_portrait_map.py` 产 chapter-map 的 bgm 段）。

| 字段 | 中文 | 类型 | 必填 | 说明 |
|------|------|------|------|------|
| id | 编号 | string | 是 | snowflake Base62 |
| name | 名称 | string | 是 | track 逻辑名（manifest.bgm 键 = 章 JSON bgm.track = wav 文件名主体），如 `晨离` |
| description | 概要 | string | 否 | 音乐定位描述（情绪/场景氛围，1-2 句） |
| prompt | 生成提示词 | string | 否 | `bgm-designer` 产出的音乐描述文字（乐器/节奏/情绪/时长/结构），供用户在外部工具手动生成 |
| audio_path | 音频路径 | string | 否 | 预制归档路径 `13_音乐/<name>.wav`（手工放入即合格） |
| mode | 播放模式 | string | 否 | `play` / `fade`（缺省 `play`，章 JSON bgm.mode） |
| loop | 循环 | boolean | 否 | 缺省 `true`（章 JSON bgm.loop） |
| status | 流程状态 | int | 否 | `0` |

**status 枚举**（无审批——音频由用户手工生成，放入文件夹即合格）：`0` 待设计 → `1` 文字描述已产出（等用户手动生成 wav）→ `2` 音频已归档（completion=2）。作废 `-1`。`NODE_STATUS` 中 BgmTrack has_approval=False。

> **生成链**：`bgm-designer`（**scene-design agent 编排**，亦可用户直触；plot-design 不查不调）读 Scene 情绪与章节设计简报 →（Scene 无关联 BgmTrack 时**自行兜底建** `BgmTrack(status=0)+has_bgm`——BGM 是场景资产，需求源于 Scene 本身）→ 生成 prompt/description 写图 + status=1 → **把文字给用户**并明示归档路径 `13_音乐/<name>.wav` → 用户手动生成放入 → 再次触发（或 dashboard 编辑器）检测文件存在置 `2`。

## 边

### 声音关联

#### has_voice_design — 角色拥有声音设计 `1:1`

- **方向**：`Character → VoiceDesign`
- **说明**：角色的基线音色（区别于 `has_voice_style` 指向 LanguageStyle 的「文字说话方式」）

| 属性 | 中文 | 类型 | 必填 | 说明 |
|------|------|------|------|------|
| sync | 同步 | boolean | 否 | 默认 `true`（角色属性变更级联重置声音设计为 -1） |

#### has_bgm — 场景关联背景音乐 `1:1`

- **方向**：`Scene → BgmTrack`
- **说明**：该场景的背景音乐（一场景一轨；发布时注入章 JSON 该场景所有 scene-block 的 bgm 字段）

| 属性 | 中文 | 类型 | 必填 | 说明 |
|------|------|------|------|------|
| sync | 同步 | boolean | 否 | 默认 `false`（BGM 是独立可复用资产，场景编辑不作废音乐） |

## ID 规则

- snowflake Base62，全局唯一，无前缀（同全项目约定）。
- 生成：`python "${CLAUDE_SKILL_DIR}/../../scripts/snowflake_base62.py" -n 1 -q`
- 引用已有角色：按 name 查（`MATCH (c:Character {name:'陆择'}) RETURN c.id`），再 `MERGE (v:VoiceDesign {id:'...'})` + `MERGE (c)-[:has_voice_design]->(v)`。
